# A. AI 사업영업본부

## A-1. RFP 가디언즈

- **팀명**: RFP 가디언즈
- **프로젝트명/아이디어명**: Claude 기반 나라장터 제안요청서(RFP) 핵심 요약 및 사업성 분석 Skill
- **접수자 본부 (Works)**: AI 사업영업본부
- **접수자 (Works)**: 임병진 차장
- **참여 대상자 (Works)**: 윤상민 부장, 임병진 차장, 오진욱 프로, 최진경 프로
- **팀원 정보 (1차접수)**:
  - 윤상민 / AX공공영업팀 / 기획
  - 임병진 / AX공공영업팀 / 시나리오 설계
  - 최진경 / AX공공영업팀 / 프론트엔드 및 UI/UX 개발
  - 오진욱 / AX공공영업팀 / 결과 검증
- **한 줄 설명**: 나라장터의 방대한 제안요청서(RFP)를 Claude AI로 즉시 분석·요약하고, AX공공영업팀의 입찰 검토 노하우를 반영한 당사 역량 매칭 알고리즘을 통해 사업 참여 여부(Go/No-Go)를 신속하게 판단하는 의사결정 지원 Skill
- **업무 카테고리**: 의사결정 지원, 업무 자동화·연계
- **업무 빈도**: 비정기
- **현재 업무의 문제**:
  - 공공사업 입찰을 위해 나라장터에 공고되는 수십~수백 페이지의 RFP를 일일이 수작업으로 검토해야 함.
  - 핵심 요구사항(참가 자격, 예산 규모, 필수 기술 스택, 수행 일정 등) 파악에 수 시간~수 일 소요. 검토 지연으로 유망 사업 기회를 놓치거나 제안서 작성 일정이 촉박해지는 고질적 문제.
  - 핵심 자격 요건 누락 시 부적격 사업에 리소스 낭비 리스크.
- **해결 방식**: Claude AI의 Long Context 능력 활용. 나라장터 RFP 파일 업로드 시 3분 이내 표준화된 'RFP 요약 리포트' 자동 생성.
  - 주요 기능 1) 핵심 요약: 사업 규모, 예산, 사업 기간, 투입 인력 요건 자동 추출
  - 주요 기능 2) 당사 맞춤형 자격 검증 및 정량 점수 산출: 당사 기업 정보(직접생산증명, 신용등급, 등록업종 등)와 RFP 요건을 비교하여 공고 요건 충족 여부 사전 스크리닝, 정량 항목 예상 점수 자동 산출
  - 주요 기능 3) 수행 실적 및 적합도 분석: RFP 요구 핵심 기술/솔루션 및 필요 실적을 당사 주요 사업 분야·과거 수행 실적 데이터와 매칭하여 사업 적합도(종합 매칭 점수) 분석 결과 제공
- **활용 AI / 툴**: Claude
- **적용 범위**: 전사 공통
- **활용 빈도**: 반복 사용, 상시 운영
- **기대 효과**:
  1. 초동 검토 시간 80% 이상 단축: 인당 평균 2~3시간 → 5분 이내
  2. 의사결정 속도 및 정확성 향상: Go/No-Go 판단 및 당사 맞춤형 정량 점수 시뮬레이션으로 수주 가능성 높은 유망 사업 선점, 제안서 준비 기간 확보
  3. 리스크 원천 차단: 제안 자격 미달(직접생산증명, 등록업종 불일치 등), 독소 조항 등을 AI 사전 감지

## A-2. 데이터 플랫폼 영업실

- **팀명**: 데이터 플랫폼 영업실
- **프로젝트명/아이디어명**: RFP 유사도 및 연관 사업 제공 AI 서비스
- **접수자 본부 (Works)**: AI 사업영업본부
- **접수자 (Works)**: 최동성 프로
- **참여 대상자 (Works)**: 소상우 부장, 박승훈 부장, 최동성 프로
- **팀원 정보 (1차접수)**:
  - 소상우 / 데이터 플랫폼 영업실 / 기획
  - 박승훈 / 데이터 플랫폼 영업실 / 기획
  - 최동성 / 데이터 플랫폼 영업실 / 기획
- **한 줄 설명**: 사업 참여 RFP 업로드시 유사 사업(유사도 표시)과 과거 참여했던 사업들 제안서들을 RFP 항목들에 맞춰 추천 제공
- **업무 카테고리**: 정보 탐색·요약
- **업무 빈도**: 주 단위
- **현재 업무의 문제**: 제안서 작성시 유사사업 제안서들 및 RFP 항목들에 대한 교차 검색 및 정보 탐색으로 인한 시간으로 생산성 저하
- **해결 방식**:
  - 데이터 전처리 및 임베딩: 기존 작성 제안서·기술 문서들을 문단(Chunk) 단위 분할. 한국어 특화 임베딩 모델(예: KoSimCSE, BGE-m3) 사용하여 텍스트 의미를 벡터 값으로 변환
  - 유사도 검색(Retrieval): 변환된 벡터 데이터를 ChromaDB 또는 FAISS에 저장. 신규 RFP 업로드 시 코사인 유사도로 가장 연관성 높은 과거 제안서 항목 실시간 검색
  - 지능형 생성(Generation): 검색된 고품질 참고 데이터와 RFP 요구사항을 GPT-4o 또는 Claude 3.5 Sonnet 등 LLM에 프롬프트로 전달. 모델이 제안서 항목별 최적화 초안 작성
  - 기술 스택: LangChain 또는 LlamaIndex (RAG), ChromaDB, OpenAI/Anthropic API (필요시 사내 인프라 내 Llama 3 등 로컬 모델 구축 가능)
- **활용 AI / 툴**: ChatGPT, 기타 (직접 입력)
- **적용 범위**: 본부 내 공통
- **활용 빈도**: 반복 사용
- **기대 효과**: 제안서 구성 및 파악에 대한 업무 생산성 30% 증가 기대

## A-3. 미리(MIRI)

- **팀명**: 미리MIRI - (Mock Insight & Review Intelligence (모의 통찰 및 검토 지능))
- **프로젝트명/아이디어명**: 나라장터 입찰 평가를 위한 가상 심사위원
- **접수자 본부 (Works)**: AI 사업영업본부
- **접수자 (Works)**: 임병진 차장
- **참여 대상자 (Works)**: 윤상민 부장, 임병진 차장, 오진욱 프로, 최진경 프로
- **팀원 정보 (1차접수)**:
  - 윤상민 / AX공공영업팀 / 기획
  - 임병진 / AX공공영업팀 / 시나리오 설계
  - 최진경 / AX공공영업팀 / 프롬프트 엔지니어
  - 오진욱 / AX공공영업팀 / 품질 검증
- **한 줄 설명**: 나라장터 입찰 제안서를 분석하여 사람이 수행(심사위원)하는 질의응답을 가상으로 자동 수행하고 평가 리포트를 생성하는 AI Skill
- **업무 카테고리**: 기타 (업무 생산성 향상)
- **업무 빈도**: 월 단위
- **현재 업무의 문제**: 제안서 사전 검증의 한계 및 모의 평가 인력·시간 부족. 제안 입찰 시 낙찰률을 높이기 위해 실제 심사위원 시각에서 제안서 사전 검증이 필수이나 제안팀 인력만으로는 다각적 관점(기술, 사업, 전략 등)의 날카로운 질의응답 시뮬레이션에 시간·인력 절대 부족. 제안서의 논리적 허점이나 예상치 못한 감점 요인을 사전에 완벽히 파악하지 못한 채 입찰 참여 리스크.
- **해결 방식**: AI 기반 가상 심사위원을 통해 다양한 질의 응답 도출. 작성된 제안서 데이터를 AI에 입력하여 기술·전략·도메인 등 다양한 성향을 가진 '심사위원'으로 빙의하여, 제안서 약점 파악 및 실제 심사장에서 나올 만한 날카로운 질의응답 자동 수행. 최종적으로 감점 예상 요인과 개선 방향이 담긴 '종합 평가 리포트' 생성.
- **활용 AI / 툴**: Claude
- **적용 범위**: 전사 공통, 외부 고객 대상
- **활용 빈도**: 상시 운영
- **기대 효과**:
  - 낙찰 경쟁력 강화: 실제 심사위원 수준 사전 검증으로 제안서 논리적 허점·감점 요인 선제적 보완, 최종 낙찰률 획기적 향상
  - 업무 효율성 및 리소스 절감: 수백 페이지 제안서 검증·모의 심사 프로세스 자동화로 기존 수일 소요 피드백을 수 시간 이내 단축
  - 영업 제안 퀄리티의 상향 평준화: 데이터·AI 기반 객관적·다각적 평가 리포트 기반 팀 전체 제안 역량 강화

  3. LLM 기반 시큐어코딩 가이드 (Context-Aware AI Guidance): 스캔 엔진 탐지 로우 데이터를 텍스트화하고 취약점 발생 코드 스니펫과 함께 Claude LLM에 전달, 즉시 복사 반영 가능한 '보안 강화된 수정 코드(Secure Refactoring)' 대시보드 매핑 제안

  - 고객사·사내 요청 대부분이 이메일로 유입, 한 통 안에 개발 수정·장애 확인·일정 문의·자료 요청·계약·정산 문의가 함께 섞임. 담당자가 프로젝트·이슈 유형·담당자·우선순위를 수기로 관리하는 과정 문제 발생

    - 경영지원(인사/재무/회계): 인사·총무·재무·법무 등 서로 다른 요청이 한 메일함에 뒤섞임, 양식·표현 사람마다 다름, 처리 이력 분산으로 재문의 대응 시간 소요, 월말·분기·연말 정산 시 재분류 필요

  - 주요 개발 항목:

    2. 보안 관련 메일 처리 기준 판단 (메일이 보안 항목이거나 Task 등록 제외 대상이면 추가 분석 중단 또는 요약 답변만 제공, 민감 정보 Task 목록 확산 차단)

    6. 모호한 요청사항에 대한 질문 생성 및 회신 메일 초안 작성

## H-8. SQLShift

- **팀명**: SQLShift
- **프로젝트명/아이디어명**: Oracle → Aurora MySQL 전환 어시스턴트 (가칭: SQLShift)
- **접수자 본부 (Works)**: 통신 AI 사업본부
- **접수자 (Works)**: 김유나 프로
- **참여 대상자 (Works)**: 김유나 프로, 김경현 프로
- **팀원 정보 (1차접수)**:
  - 김유나 / AI 망운용 플랫폼 개발팀 / Skill 설계 · 변환 엔진/프롬프트 개발
  - 김경현 / AI 망운용 플랫폼 개발팀 / Skill 설계 · 변환 엔진/프롬프트 개발
- **한 줄 설명**: Oracle 전용 SQL·MyBatis 매퍼를 Aurora MySQL 호환 문법으로 일괄 변환하고, 난이도 자동 분류로 견적 산정을 지원하며, 실행계획 해석까지 커버해 클라우드 전환 사업의 DB 마이그레이션 전 과정 공수를 줄이는 AI 어시스턴트
- **업무 카테고리**: 데이터 처리·분석, 업무 자동화·연계
- **업무 빈도**: 비정기
- **현재 업무의 문제**: SK텔레콤 OSS 등 레거시 시스템을 AWS Aurora MySQL로 전환하는 클라우드 마이그레이션 사업에서 다음 세 가지 문제 복합 발생.
  - [수작업 변환 부담] Oracle 전용 SQL 문법(NVL·DECODE·ROWNUM·SYSDATE·시퀀스·(+) 외부조인·MERGE·CONNECT BY·PIVOT 등)과 데이터타입(NUMBER·VARCHAR2·CLOB)을 MySQL 호환으로 일일이 변환 필요. 실제 경험 기준 고급개발자·주니어 2인이 AI 일부 활용해도 주당 약 200건 처리가 한계, 1,000건 규모 프로젝트에서 5주 이상 소요. 특히 CONNECT BY(계층 쿼리)·PIVOT·NULL/빈문자열 처리처럼 문법만 다른 것이 아니라 쿼리 결과 자체가 달라질 수 있는 케이스는 높은 집중도·도메인 지식 요구
  - [MyBatis 레이어 공백] AWS SCT는 스키마 변환 위주여서 애플리케이션 SQL과 MyBatis 매퍼(<if>·<foreach>·sqlId 참조·rowId 반환 등 동적 쿼리 포함) 변환은 전적으로 사람이 담당
  - [견적·검수의 불확실성] 변환 경험 없는 담당자는 난이도 과소평가해 하루 10건으로 산정하는 등 일정 오류 발생, 검증은 실행 결과 비교·반환 시간 체크 수준에 그침. 실행계획 읽을 수 있는 개발자가 드물어 DBeaver에서 EXPLAIN 결과 확인해도 활용 못하는 경우 多
- **해결 방식**: Oracle SQL/MyBatis 매퍼 입력 시 5단계 파이프라인 처리.
  - ① [문법 변환 엔진] 단순 함수 치환(NVL→IFNULL, SYSDATE→NOW() 등)부터 의미가 달라지는 케이스까지 자동 변환. 변환 예시: CONNECT BY(계층 쿼리)→WITH RECURSIVE CTE, PIVOT→조건부 집계(CASE+GROUP BY), NULL/빈문자열 처리 차이 보정, Oracle 힌트(NO_MERGE 등)→MySQL 동등 힌트 또는 제거 판단. 단순 텍스트 치환 X, 의미 보존 변환 핵심
  - ② [MyBatis 동적 쿼리 처리] <if>·<foreach>·<choose> 태그 내부 Oracle 문법, sqlId 참조 구조, rowId 반환 후 Java 서비스 연계 패턴 등 AWS SCT 미처리 애플리케이션 레이어 커버
  - ③ [난이도 자동 분류 & 견적 산정 지원] Easy/Medium/Hard로 태깅하여 "AI 처리 가능 vs 사람 검수 필요" 판단 기준 제공. 실제 프로젝트에서 변환 경험 없는 담당자가 하루 3건으로 산정하는 등 견적 오류 사례 데이터 기반 보정
  - ④ [수동 검토 리포트] 자동 변환 불가 항목 목록화 및 이유 설명
  - ⑤ [실행계획 해석 도우미] MySQL EXPLAIN 결과 붙여넣으면 풀스캔 여부·조인 순서·인덱스 활용 현황 등을 한국어로 풀이, 인덱스 추가·PK 선추출 후 재조인 패턴 등 구체적 튜닝 포인트 제안
  - [사내 노하우 베이스 & 이력 관리] 팀이 검증한 튜닝 패턴(커스텀 함수→스칼라 쿼리 대체, 조직 계층 데이터 조회 최적화 패턴 등)을 등록하면 유사 쿼리 자동 적용. 프로젝트별 변환 이력 저장으로 재사용 및 검수 자료 활용. 개인 노하우를 조직 자산으로 전환하는 AI가 핵심 포지셔닝
- **활용 AI / 툴**: Claude, 자체 개발
- **적용 범위**: 전사 공통
- **활용 빈도**: 반복 사용
- **기대 효과**: 본 Skill은 사용자 유형별로 서로 다른 가치 제공하는 전사 공통 도구로 설계.
  - [클라우드 전환 사업 개발자] 주당 200건 수준이던 수작업 변환 속도 대폭 향상, DB SQL·매퍼 변환 공수 약 70% 단축. CONNECT BY·PIVOT·NULL 처리 등 결과가 달라지는 케이스 자동 안내로 휴먼 에러 감소
  - [PM / 영업 담당자] 난이도 자동 분류 결과 기반 프로젝트 견적·일정 산정 정확도 향상. 변환 경험 없이도 "Hard 케이스 몇 %" 데이터로 현실적 공수 산출
  - [일반 개발자 (DBA 비전문가)] 실행계획 해석 도우미로 EXPLAIN 결과 직접 읽지 않아도 병목 지점·튜닝 방향 파악 가능. DBeaver 한계 AI 보완
  - [조직 전체] 팀 축적 튜닝 노하우를 Skill 등록하면 다음 프로젝트 자동 재사용. 개인 노하우를 조직 자산으로 전환하는 구조. 회사 핵심 전략 방향인 SK텔레콤 OSS 클라우드 전환 직접 가속, 모든 클라우드 전환 사업에 재사용 가능한 전사 표준 도구로 발전 가능

- **현재 업무의 문제**: 인수인계는 모든 조직에서 반복 발생하지만 전임자 기억·문서화 습관·퇴사·발령 전 여유 시간에 의존. 담당자 변경·조직개편·프로젝트 이관·장기 휴가 등은 팀 단위로 매년 반복 발생, 업무 맥락 단절 발생.
  - 상황별 문제: 담당자 퇴사·발령(인수인계 문서 부재/미현행화 → 신규 담당자 업무 구조 재파악), 프로젝트 장기화(의사결정 근거가 메일·티켓·메신저·문서 분산 → "왜 이렇게 결정됐는지" 확인 어려움), 반복 장애·이슈(과거 유사 기록 미발견으로 매번 처음부터 분석 → 대응 시간 증가·동일 실수 반복), 전임자 부재(확인 불가 → 조직 지식이 개인과 함께 소멸), 신규 담당자 투입(핵심 맥락 파악까지 2~4주 → 업무 공백·일정 지연·품질 저하), 인수인계 품질 편차(작성자별 상세도·관점 차이 → 누락·후속 담당자 혼란)
  - 현재 인수인계 문서는 전임자가 퇴사·발령 직전 직접 작성하며 평균 1~2일 이상 소요. 그러나 잔여 업무·승인·정리 회의 몰림으로 핵심 의사결정 배경·미결 리스크·이해관계자 정보 누락. 인수인계 품질이 조직 표준 프로세스가 아니라 전임자 성실함·기억력에 의해 결정. 기존 인수인계 방식은 "담당자 변경 발생 후에야 문서 작성하는 사후 대응 방식".
- **해결 방식**: 메일·회의록·Jira 티켓·문서 등 흩어진 업무 기록 수집 후, AI가 시간순으로 재구성하여 업무 히스토리와 인수인계 문서 자동 생성.
  - 1차 구현: 사내 시스템 전체 연동이 아닌 파일 업로드 기반 MVP. 사용자가 프로젝트명·관련 문서 묶음 입력 시 Streamlit 기반 웹 UI가 파일 수집, Python 파싱 모듈이 PDF/DOCX/CSV/TXT 문서에서 본문·메타데이터 추출. 검색·필터링 모듈이 프로젝트명·키워드·날짜·담당자 정보 기준 관련 문서 선별·중복 제거. 선별 문서를 날짜 기준 정렬하여 업무 타임라인 변환.
  - Claude API가 타임라인과 문서 본문 기반 업무 시작 배경·주요 의사결정·담당자 변경 이력·미결 이슈·반복 리스크·신규 담당자 확인 질문 단계별 추출. 분석 결과는 원본 문서와 매핑되어 각 요약 항목마다 출처와 신뢰도 높음/중간/낮음 표시. Python Rule-based Scoring 모듈이 인수인계 완성도 점수와 업무 기억 부채 점수(Knowledge Debt Score) 계산.
  - 최종 결과: 표준 인수인계 문서, 3분 브리핑, 첫 3일 액션 플랜, 필독 문서 TOP 5, 신규 담당자 질문 리스트, 업무 히스토리 카드, 원본 근거 목록. Streamlit 화면 확인 또는 Markdown/DOCX 다운로드.
  - 11일 내 데모: 비식별 샘플 데이터와 파일 업로드 방식. 이후 고도화 단계에서 Jira·Confluence·Slack·메일 API 연동하여 일상 업무 기록 자동 축적 구조 확장.
  - 주요 기능 16종: 업무 히스토리 자동 수집 / 일상 업무 기록 자동 축적 / 시간순 타임라인 복원 / 의사결정 포인트 추출 / 미결 이슈 탐지 / 담당자·이해관계자 맵 생성 / 필독 문서 TOP 5 추천 / 리스크·주의사항 요약 / 3분 브리핑 생성 / 인수인계 문서 자동 생성 / 원본 근거 목록 제공 / 근거 기반 신뢰도 표시 / 인수인계 완성도 점검 / 신규 담당자 질문 리스트 생성 / 업무 히스토리 카드 생성 / 업무 기억 부채 점수 산출
  - AI 신뢰도 표시 기준: 높음(2개 이상 원본 문서 동일 내용 확인-확정 가능) / 중간(1개 문서 확인-확인 권장) / 낮음(추정-담당자 확인 필요). 인수인계 문서에서 출처 없는 내용은 확정 X, "추정"/"확인 필요" 표시.
  - 인수인계 완성도 점검 항목: 업무 배경, 현재 상태, 담당자, 의사결정, 미결 이슈, 리스크, 다음 액션, 근거 링크
  - 업무 기억 부채 점수 평가 항목: 문서 최신성, 담당자 집중도, 미결 이슈 수, 근거 부족 항목, 필독 문서 부재, 확인 필요 질문 수
- **활용 AI / 툴**: ChatGPT, Claude, 자체 개발, 기타(파일 업로드 기반 RAG, PDF/CSV/Markdown/DOCX 파서)
- **적용 범위**: 본부 내 공통
- **활용 빈도**: 반복 사용, 상시 운영
- **기대 효과**:
  - 정량적: 인수인계 문서 작성 시간 90% 이상 단축 (전임자 1~2일 → AI 초안 1분, 검토 포함 30분 이내), 신규 담당자 맥락 파악 기간 단축 (2~4주 → 3~5일), 핵심 문서 탐색 시간 단축 (반나절~1일 → 5분 이내), 반복 이슈 재분석 시간 단축 (30분~수 시간 → 5~10분 이내), 인수인계 누락 항목 완성도 점수 사전 점검, 업무 기억 부채 점수 인수인계 리스크 사전 감지, 전임자 부재 시에도 기록 기반 복원 가능
  - 정성적: 개인 기억 의존 → 조직 검색 가능 자산 전환, 전임자 부재 시 과거 의사결정 배경 복원, 인수인계 품질 표준 프로세스 관리, 신규 담당자 초기 시행착오·업무 공백 감소, 반복 장애·반복 이슈 대응 속도 향상, 프로젝트별 히스토리 카드 축적으로 조직 지식 자산화, 팀장·리더가 담당자 변경 리스크 사전 관리, 업무 기억 부채 점수로 팀장 선제 대응
  - 전사 확산 가능성: 개발팀(시스템 개편·장애 이력·API 변경 인수인계), 운영팀(반복 배치 실패·고객 이슈·운영 정책 변경 히스토리), 영업팀(고객사 협의 이력·계약 쟁점·제안 진행 상황 인수인계), 인사팀(채용·평가·제도 개편 히스토리), 재무팀(정산·비용 승인·감사 대응 이력 관리)

## 부록 — 1차접수 docx와 Works PDF 간 표기 차이 메모

본문 각 팀 섹션에는 양쪽 내용을 모두 반영했다. 다음은 두 문서 간 명백히 다르거나 한쪽에만 있는 표기 정리:

- **DOCS**: 1차접수에는 아이디어명 미기재. Works에 프로젝트명 "취약점 점검 리포트 자동화"로 등록.
- **Dr.MOBI**: 1차접수 아이디어명 "/ai-review — AI 사용 역량 진단 및 성장 리포트" ↔ Works 프로젝트명 "AI 자가진단 Dr.MOBI".
- **MOAI Beginners**: 1차접수 "Probe 통합 모니터링툴 AI Assistant 기반 ONEVision Probe 장애/작업 자동 분석 및 리포트 Skill" ↔ Works "Probe 운영 리포트 자동 생성 Skill". 또한 1차접수 팀원 3명(홍종수·한재구·김지훈) ↔ Works 접수자는 박동진 프로(1차접수 팀원 명단에 미등재).
- **MOLENDER**: 1차접수 "일일 업무 기록 자동화 Skill (/work-log)" ↔ Works "업무 기록 자동화 MOLENDER".
- **MOBOT**: 1차접수 "사내 AI 챗봇 - 규정 질의·신청·담당자 연결 통합 Skill" ↔ Works "사내 챗봇 MOBOT".
- **즐거운 용역 관리**: 1차접수 "나라장터 사전규격 AI 자동분석 및 제안서 초안 생성 시스템" ↔ Works "즐거운 용역 관리 시스템".
- **FieldDoc AI**: 1차접수 "현장 점검 결과 보고서 자동 생성 AI Skill" ↔ Works "FieldDoc AI".
- **PeopleOps AI**: 1차접수 팀원 1명(이미선), Works 참여대상자 1명(동일).
- **백스테이지**: 1차접수 5명 ↔ Works 접수자(황민영) + 참여대상자 4명(김주만·이동민·임진·정해영), 총 5명(중복 없음).
- **즐거운 용역 관리, MOBIS**: Works PDF의 프로젝트 상세 설명이 1차접수 docx보다 더 길게 작성됨 (1차접수 항목 외 추가 설명·구현 현황 포함). 본문은 두 출처 모두 반영.
- **TaskRadar**: 1차접수 해결 방식은 1문장, Works PDF에 "마감·진척·정체·유형 네 축으로 점수, Apps Script Web App으로 구현"이라는 보강 정보 추가.
